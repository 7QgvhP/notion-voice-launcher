# 0005. ロック解除を省略する方式を採用しない

- ステータス: Accepted
- 日付: 2026-09-20 以前

## 背景（Context）

画面ロック中に起動されると、アクティビティはシステムによってロック解除まで保留される。ロック中でも、解除操作なしで音声入力まで到達したかった。

## 決定内容（Decision）

アプリ側でロック解除（認証）を省略する仕組みは入れない。ロック中の起動は、OS の動作（解除まで保留し、解除後に Notion を開く）に任せる。
解除操作なしで到達したい場合は、Android の Smart Lock を使う（手順は [usage.md](../usage.md)）。

## 理由と検討した代替案（Consequences / Alternatives）

検討した代替案：`showWhenLocked` と `requestDismissKeyguard` を使う方式。実機で検証し、次の理由で採用しなかった。

- 指紋認証のプロンプト（ALTERNATE_BOUNCER）を即座に出すところまでは動くが、認証自体は省略できない（`dumpsys trust` で `deviceLocked=1` のまま）。
- アクティビティがロック画面を覆い隠すため、プロンプトが自動で引っ込んだときに、壁紙だけの画面に取り残されて解除しづらくなる。
